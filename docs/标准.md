# instrumentationx 标准

**角色**：可观测性注入点契约（唯一公开物：`Instrumentation` trait）。
**状态**：crate 首版（0.1.0），方法集合为稳定面。

## 1. 定位

- 本 crate 零依赖、只定义一个对象安全的同步 trait，解耦「观测实现」与「观测消费方」。
- 不含任何具体实现；实现方见 `observex`，消费方见 `resiliencx`。
- 双方互不依赖，不形成循环或反向业务依赖。

## 2. 契约标准

- 三方法 `record_retry(op, attempt)` / `record_circuit_open(op)` /
  `record_circuit_close(op)` 是方法集合稳定面；**新增方法属破坏性变更**。
- `attempt` 起点（`0` / `1`）由调用方约定，实现方不得假设。
- 同一次熔断状态迁移只应记录一次（open 与 close 各自对应一次迁移）。
- trait 必须对象安全（无泛型方法、无 `Self: Sized`、无关联类型、无 async fn）。

## 3. 实现方义务

- 必须满足 `Send + Sync`。
- 写入观测后端前必须清理并限制 `op`（控制字符 / 超长 / 换行——防日志注入与存储放大）。
- 不应阻塞调用方：`record_*` 计入消费方热路径。
- 不应在 `record_*` 中 panic；内部错误只能内化（计数、丢弃或降级）。

## 4. 消费方义务

- 只持有 `&dyn` / `Arc<dyn>`，不依赖具体实现类型。
- `op` 使用稳定分层操作名，不拼接高基数字段。
- `attempt` 语义在消费方内保持一致。

## 5. 验收

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo package --no-verify
```

测试覆盖：对象安全、`dyn` 跨线程共享、三方法的调用计数往返（见 `tests/`）。
